## Task

Create `docs/score-inventory.md`. For every numeric/percentage/gauge/grade
surfaced to the user (plus the borderline categorical ones noted below),
add one table row with these columns:

| Score | Where shown (file:line) | Definition (file:line) | Evidence basis (1 line) | Decision | Justification (1 line) |

**Decision** must be exactly one of `keep`, `demote-to-rank`, `remove`,
or `n/a (not user-facing)`. Apply this rubric consistently:

- **keep** — the number is computed directly from an objective, externally
  verifiable measure (raw price/volume data, ATR, a real external API, a
  correlation coefficient, or genuine settled forward-test/tracker outcomes
  with a disclosed sample size) and its label doesn't overclaim statistical
  meaning it doesn't have.
- **demote-to-rank** — the number is real and internally consistent but is a
  rule-based/weighted-heuristic score dressed up as a precise percentage or
  "confidence" (implying calibrated probability or proven edge) without
  forward-test validation. Decision means: stop showing a bare 0–100/percent
  figure: replace with a qualitative band/rank or add an explicit
  "heuristic, not a proven-edge probability" disclosure. Also applies to any
  score with a silent fallback path that changes its meaning without telling
  the user.
- **remove** — the number is actively misleading with no reasonable fix
  short of deletion, or duplicates another score under a confusingly similar
  label such that keeping both invites misinterpretation.
- **n/a (not user-facing)** — computed and stored but never rendered in the
  web UI (fine to leave as-is; note it so the inventory is complete).
