# EDR 0006: Unified live-price architecture (WebSocket overlay on REST snapshots)

- **Status:** Accepted, implemented (2026-07-10)
- **Scope:** New `src/lib/engine/symbol-map.ts`, `src/lib/engine/binance-live-feed.ts`, `src/stores/live-prices.ts`, `src/hooks/useLiveUniverseSubscription.ts`. Changed: `src/hooks/useLivePrice.ts` (thin wrapper, signature unchanged), `src/hooks/queries/index.ts` (`useAssets`/`useTopAssets`/`useMarketSnapshot`), `src/lib/engine/binance.ts`, `src/lib/engine/market.ts`, `src/lib/engine/perp.ts`, `src/lib/engine/alignment.ts`, `src/lib/engine/symbols.ts`, `src/components/iq/top-bar.tsx`, `src/routes/token.$symbol.tsx`, `src/routes/tracker.tsx`, `src/routes/__root.tsx`.
- **Depends on:** none. Read alongside this repo's `no-native-websocket-support` finding (own-server push has no upgrade path here) — irrelevant to this work, since every socket here is the browser connecting directly to Binance, never through this app's Nitro server.

## Problem

Live price only ever existed inside `useLivePrice`, wired into exactly two components (`token.$symbol.tsx`, `tracker.tsx`). Every other price surface — dashboard, `markets.tsx`, `rankings.tsx`, sector rotation, watchlist-via-rankings — read only the REST `MarketSnapshot`, refreshed every 30–45s. Root-cause tracing also found: symbol normalization duplicated across seven call sites with no awareness of Binance's contract-multiplier futures symbols (`PEPE` spot vs `1000PEPEUSDT` perp, a real 1000x price difference), and `tracker.tsx` forwarding no `market` to `useLivePrice`, so perp-recorded tracked signals silently priced their live R-multiple off the spot feed.

## The chosen architecture

**Symbol resolution, once.** `symbol-map.ts`'s `resolveExchangeSymbol(ticker, market)` is the single place that knows an internal ticker's actual Binance exchange symbol and price scale per market. A static override table (`PEPE → 1000PEPEUSDT` at scale 1000, plus a dozen more confirmed against live `fapi.binance.com/fapi/v1/exchangeInfo`) handles Binance's contract-multiplier futures bases. `binance.ts`'s two REST fetchers apply the scale correction immediately after parsing Binance's response — divide OHLC/price, multiply base-asset volume, leave `quoteVolume`/open-interest-value untouched (already real USDT notional, invariant under the scale). Every downstream consumer (quant engine, chart, risk plan, funding/OI in `perp.ts`) sees real per-token units regardless of market, with zero awareness of the quirk. Seven duplicated normalize-ticker regexes were consolidated to call `normalizeTicker` from the same file.

**A Binance-specific multiplexed feed, not a "provider-agnostic" one.** `binance-live-feed.ts` maintains at most two long-lived WebSocket connections total — one per market — using Binance's combined-stream endpoint. Consumers register a single ticker+market "want" under their own stable id (`registerLiveInterest`/`unregisterLiveInterest`); replacing or deleting a caller's own registry entry is idempotent, so React StrictMode's mount→cleanup→mount double-invoke can't drift a count the way an integer refcounter would. Whenever the union of wanted tickers changes for a market, the manager closes and reopens that market's socket with the full desired stream list baked into the connect URL, rather than maintaining incremental `SUBSCRIBE`/`UNSUBSCRIBE` protocol state. Reconnect (capped exponential backoff, matching the pre-existing single-symbol hook's cadence) always re-reads the _current_ wanted set at connect time, never a value captured when the retry was scheduled.

**Ephemeral store, thin hook.** `live-prices.ts` is a deliberately non-persisted zustand store (every other store in `src/stores/` persists to localStorage; this one holds WS ticks, not user state). `useLivePrice(symbol, enabled, market)` keeps its exact pre-existing external signature — it's now a thin wrapper: register/unregister on mount via `useId()`, read the tick back via a store selector. `token.$symbol.tsx` and `tracker.tsx` needed no call-site changes beyond the market-forwarding fix below.

**Dashboard overlay, kept out of the selector's side effects.** `useLiveUniverseSubscription`, mounted once in `__root.tsx` alongside the app's other always-on hooks (`useNotificationStream`, `useSignalSettlement`, `useTriggerAlerts`), keeps the whole `UNIVERSE` subscribed for whichever market is active — a pure side effect, deliberately not folded into `useAssets()` itself so that selector stays a plain data hook (a future caller of `useAssets()` shouldn't be surprised into opening sockets). `useAssets()` merges each asset's live tick over REST `price`/`change24h` when one has arrived, preserving the full `useQuery` result shape (`isLoading`/`error`/etc.) so every existing call site — dashboard, `markets.tsx`, `rankings.tsx`, watchlist-via-rankings — gets live-ticking prices for free.

**The nav-bar switch is a real mode switch.** `marketType` was already a single global preference; the Spot/Perp toggle moved from `token.$symbol.tsx`'s header into `top-bar.tsx`, same store binding. `market.ts`'s `computeSnapshot(market)` now has one 45s-TTL cache entry per market instead of a single global one, and fetches the UNIVERSE's klines (plus BTC's regime-classification daily candles) against whichever market is active, through the same symbol-map resolution. Flipping the switch recomputes regime/rotation/sector/technical from perp klines, in addition to the live-tick overlay.

**Fix, independent of everything else:** `tracker.tsx`'s `TrackedSignalRow` now forwards `signal.market ?? "spot"` — a tracked signal's own recorded market always wins over the global preference.

## Choices recorded (and what was rejected)

- **Idempotent caller registry over integer refcounting.** A generic reference-counted subscribe/unsubscribe manager with an idle-teardown grace timer was the original design. Rejected on review: this app has a handful of subscription sources (the universe subscriber, the one open token page, tracker rows), all changing at human-navigation pace, not tick pace — refcounting's composability benefit (arbitrary independent callers) isn't earned at this scale, and it introduces a real race class (StrictMode double-invoke drift, reconnect races against a captured wanted-set) that the idempotent-replace-by-id model structurally can't have.
- **Reconnect-by-full-URL-replacement over incremental SUBSCRIBE/UNSUBSCRIBE.** Since the wanted set changes rarely, closing and reopening a socket with the complete stream list is simpler than protocol-message bookkeeping and request-id tracking, at the cost of a sub-second tick gap on navigation — imperceptible for a personal dashboard. Revisit only if that gap ever becomes a real, observed problem.
- **`priceScale` is real, not premature.** Confirmed against live Binance data: spot lists `PEPEUSDT` at the real per-token price; futures lists only `1000PEPEUSDT` (base asset `1000PEPE`), quoted per 1000 tokens — omitting the correction wouldn't break ratio-based trading logic, but would misrepresent the displayed/compared price by 1000x. Correcting once at the REST-fetch boundary (not at display call sites) avoids threading the scale factor through every formatter.
- **Named `binance-live-feed.ts`, not `live-price-feed.ts`.** The combined-stream URL shape, the miniTicker envelope, and `MarketType`'s spot/perp split are all Binance-specific; calling the module "provider-agnostic" would overclaim genericity not yet built. The ticker-keyed store shape doesn't need to change to add a second exchange later, but the feed manager and `MarketType` do — that's deferred until there's a real second provider to design against, not guessed at now.
- **REST snapshot as bootstrap/source of truth, ticks as overlay only** — never the reverse. A tick overrides `price`/`change24h` only once one has arrived; the dashboard degrades to exactly today's REST-only behavior if the feed hasn't ticked yet or is unreachable.
- **Rejected: leaving multiplier-based futures symbols unsupported in perp mode.** A defensible lower-effort alternative, but a real capability regression for a fix this small (one table, one divide/multiply).
- **Out of scope:** `symbols.ts`'s tradability check (search autocomplete, token-page 404) stays spot-only. Binance-listed symbols that exist only on perp remain unreachable — a separate follow-up if wanted.

## Assumptions and edge cases

- SSR: the feed manager guards `typeof WebSocket === "undefined"` inside `registerLiveInterest`/`reconcile` itself (defense in depth), not only by relying on call sites being effect-wrapped.
- A UNIVERSE ticker with no listing at all on a given market (none currently — all 18 confirmed against live `fapi.binance.com` exchangeInfo, PEPE via the override) would fail that one asset's REST fetch and fall back to its own mock candles inside `buildSnapshot`, per the pre-existing partial-failure tolerance (`source: "live"` if ≥half of UNIVERSE returns ≥48 candles) — never fails the whole snapshot.
- Volume scale only matters for absolute-dollar display; `quant.ts`'s use of volume is a ratio against its own history and is scale-invariant.
- Stale ticks for a ticker that's no longer wanted are deleted from the store at reconcile time, not left to accumulate.

## Verification performed

- Live REST verification against the running dev server: `/api/klines?symbol=PEPE&market=perp` now returns real per-token-scale candles (~2.665e-06) matching `market=spot` (~2.67e-06), instead of the pre-fix 1000x-inflated raw contract price (or an empty array, since `PEPEUSDT` doesn't exist on futures at all).
- `resolveExchangeSymbol` spot-checked for BTC (unscaled) and PEPE (rename + scale 1000) — matches live Binance exchangeInfo.
- `bunx tsc --noEmit` and `bun run lint` clean after every commit.
- **Not verified in this pass:** live WS tick delivery through an actual browser session — this sandbox's outbound WebSocket connections to Binance are blocked (confirmed: the identical, pre-existing single-stream URL shape also receives zero frames here despite an open connection, while the equivalent REST calls succeed), so the feed manager's message-handling path is verified by code review and by matching the pre-existing hook's proven frame-parsing shape, not by an observed live tick. Recommend a real-browser check: open the dashboard, watch prices tick between snapshot refetches; flip the nav-bar switch and confirm regime/rotation numbers and PEPE's perp price both update; open the tracker with a perp-recorded signal and confirm its R-multiple moves with the perp feed.

## Future extension points

1. **A second exchange provider** — design `resolveExchangeSymbol`'s provider dimension and a parameterized feed manager once a real second exchange exists, not before.
2. **Market-aware tradability checks** in `symbols.ts`, to surface the ~294 Binance symbols that exist only on futures.
3. **Incremental SUBSCRIBE/UNSUBSCRIBE**, only if the reconnect-on-change tick gap is ever observed to matter in practice.
